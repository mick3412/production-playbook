# 影片製作構想流程：整合「外部同類型範本搜尋」完整計畫

## 1. 背景與現況缺口

對照目前 `production-playbook` 的前置構想流程（[00-開案.md](../guide/00-開案.md)、[01-研究與參考.md](../guide/01-研究與參考.md)），現有工具鏈已具備不錯的**方向對齊**與**單片拆解**能力，但在「如何針對新需求從外部找出對的範本」上存在兩個斷點：

1. **「1.0 方向對齊」只看本地固定樣本庫**
   [direction.py](../bin/direction.py) 目前的 6 題二選一與「參考牆」依賴預先建好的本地 `FlexClip` 語料庫（`direction_index.json`）。遇到新產業、新題材或特定平台的流行敘事結構時，缺乏「針對這次需求去外面找同類型實戰影片」的環節。
2. **「1.1 找參考」只有檢查清單，缺乏搜尋與篩選管線**
   [tools.md](../guide/tools.md) 已收錄 `yt-dlp`（`T-34`）、動態參考圖庫（`T-72`）、`youtube-agent-skill`（`T-74`）、Gemini 影片理解（`T-132`），但缺少一條把「**依需求搜尋 → 量化初篩 → 負責人挑片 → 拆解進方向卡**」串起來的自動化/半自動化流程。

---

## 2. 目標流程設計

將「外部同類型範本海選」放在 `0 開案` 之後，與 `1.0 方向對齊` 並流，避免先用通用樣本定完方向、後面才發現該領域的主流做法完全不同。

```text
[0 開案] brief.md（確定平台、比例、時長上限、形式、受眾）
   │
   ▼
[1.0a 外部範本海選（零下載）]
   ├─ 先查本地已驗證參考庫（direction_index.json）
   └─ 不足時外部搜尋 → 抓 Metadata + 縮圖 + 指標計算（限 5–10 支候選）
   │
   ▼  (選擇性：用 Gemini 影片理解 T-132 免下載看前 3 秒鉤子與大綱)
   │
[關卡：負責人勾選 2–3 支 + 同意下載 (S1-07)]
   │
   ▼
[1.0b / 1.2 量化拆解與方向對齊]
   ├─ yt-dlp (T-34) 下載核准片
   ├─ video_probe.py breakdown 算出每鏡秒數、亮度、飽和度、畫面變化、字面積
   ├─ 填入 L1–L4 參考表（標明「借什麼」與「不借什麼」）
   └─ 併入 direction.py 參考牆 → 產出 direction.json 方向卡
   │
   ▼
[資產沉澱] 將核准並拆解後的範本寫回本地參考索引，供下次專案優先複用
```

## 3. 五個核心設計考量

### 3.1 流程位置與職責邊界
* 外部範本不是用來「照抄畫面」，而是用來**校準該領域的結構基準**（前 3 秒怎麼留人、資訊密度多高、每鏡大約幾秒、常用字幕與版面配置）。
* 必須在 `brief.md` 確定規格後才搜，否則搜尋條件會發散。

### 3.2 搜尋與篩選維度（怎麼算「對且值得學」）
單純用關鍵字搜「觀看數最高」容易選到大品牌或大網紅靠粉絲基數衝出的高觀看影片，結構不可複製。篩選拆成三層：

1. **類型與規格對齊（硬過濾）**
   * 平台與畫幅：9:16 短影音（Shorts / Reels / TikTok）vs 16:9 長片。
   * 表現形式：口播、畫面旁白、文字動態、UGC 實拍、產品操作演示。
   * 時長區間與語言市場：與 `brief.md` 一致。
2. **有效性指標（實作 `S1-09`）**
   * **有機內容（YouTube / Shorts）**：優先看**離群倍數（Outlier Score = 該片觀看 ÷ 該頻道近期 10–15 支影片中位數）**或**觀看／訂閱比（Views / Subs ≥ 3x）**，找出「小頻道也爆、靠內容結構取勝」的範本。
   * **商業／投流廣告（Meta / TikTok）**：無法取得觀看數時，改看**投放持續天數**（持續投放超過 14–30 天仍未下架，通常代表轉換率有效）。
3. **製作可行性過濾（防呆）**
   * 排除需要實拍大棚、明星代言、重度 3D 特效等超出目前工具鏈與預算的範本，優先保留「現有手冊工具鏈做得出來」的參考。

### 3.3 兩階段決策機制（防止「無限滑片」與「盲目抄襲」）
* **Stage A（海選，零下載）**：只抓 Metadata（標題、片長、觀看、離群倍數、發布時間）＋ 縮圖 ＋ 網址，限制每次只輸出 **5–10 支**候選清單，讓負責人在 3 分鐘內勾選 **2–3 支**。
* **Stage B（拆解，才下載）**：負責人勾選後才觸發下載與 `breakdown`，並強制在參考表寫出：
  * **要借的點**（如：前 3 秒問題反問、每鏡 1.8 秒快切、高對比黃字重點）。
  * **不借的點**（如：原片實拍場景、特定口頭禪、過度轉場特效）。

### 3.4 版權、平台風控與成本控管
* **版權與合規（`S1-07`、`T-34`）**：下載外部影片前必須先列清單請負責人同意；外部影片僅供拆解與量化抽樣，**絕不放進成品**。
* **成本上限（`S0-10`）**：YouTube Data API v3 免費配額與 `yt-dlp` 為零成本；若後續接入付費爬蟲（如 Apify）或大量呼叫影片理解 API，須在海選前先列預估費用與筆數上限。
* **快取與節流**：對同一組關鍵字的搜尋結果做本地快取，避免頻繁請求觸發平台風控。

### 3.5 長期資產沉澱
* 每次專案核准並拆解的外部範本，其 `breakdown.json`、標籤（形式、產業、節奏、配色）與來源網址應自動整理進本地參考索引，讓同類型需求越做越快。

## 4. 適合加入的工具盤點與比較

### 4.1 零成本立即可接的基礎管線（YouTube / Shorts）
| 工具 | 定位 | 優勢與接法 | 限制 / 注意 |
| :--- | :--- | :--- | :--- |
| **`yt-dlp`（手冊已有 `T-34`，擴充用法）** | 關鍵字海選＋Metadata 過濾 | 用 `ytsearch15:"關鍵字"` 搭配 `--match-filter "duration <= 65 & view_count > 10000"` 與 `--dump-json --no-download`，**不下載影片**即可取得片長、觀看、頻道、縮圖與網址。 | 單靠 `ytsearch` 無法取得該頻道近期中位數，無法單獨算出 Outlier Score。 |
| **YouTube Data API v3（自建腳本）或 `yt-outlier-mcp`** | 同領域爆款／離群影片偵測（實作 `S1-09`） | 開源專案 [`phillipmex/yt-outlier-mcp`](https://github.com/phillipmex/yt-outlier-mcp) 或 [`pandich93/youtube-niche-finder`](https://github.com/pandich93/youtube-niche-finder) 可用官方 API 計算 `Views / Subs` 與「頻道近期中位數倍數」，並支援 MCP 直接讓 Agent 查詢。 | 需申請免費 YouTube Data API Key（每日配額 10,000 units，開案海選足夠使用）。 |

### 4.2 商業廣告／短影音競品庫（適合行銷轉換型影片）
| 工具 | 定位 | 優勢與接法 | 限制 / 注意 |
| :--- | :--- | :--- | :--- |
| **TikTok Creative Center（Top Ads）** | TikTok 熱門廣告與高互動結構 | 官方免費，可依產業、地區、轉換目標篩選，並直接檢視腳本節奏與前 3 秒鉤子。 | 缺乏穩定的官方公開搜尋 API，偏人工瀏覽；自動化需第三方爬蟲。 |
| **Meta Ad Library（＋ MCP / Apify）** | FB / IG 競品影片廣告搜尋 | 可查競品正在投放的影片素材、文案與**開始投放日期**（用來判斷長青有效素材）。 | 官方網頁免費；若需由 Agent 自動批次抓取，通常需接 **Apify** Actor 或第三方 MCP（按量計費，需依 `S0-10` 設上限）。 |

### 4.3 視覺風格、鏡頭語言與動態參考庫（適合品牌片／高質感需求）
| 工具 | 定位 | 優勢與接法 | 限制 / 注意 |
| :--- | :--- | :--- | :--- |
| **Eyecandy / 24fps / Motionographer（手冊 `T-72` 已有）** | 運鏡、轉場、動態設計靈感 | 人工策展品質高，適合找 `L3 部位`（轉場、運鏡）與 `L4 細節`。 | 多數無公開搜尋 API，適合人工挑片後再丟網址進來拆解。 |
| **Flim（flim.ai） / ShotDeck** | AI 語意畫面／構圖／打光搜尋 | 支援自然語言描述畫面氛圍、景別、色調去搜廣告、MV 或電影畫面，適合對齊高階視覺調性。 | 屬付費資料庫（或免費額度有限），不適合找口播／資訊型短影音結構。 |

### 4.4 海選後的「免下載初篩」與「量化拆解」銜接
| 工具 | 在流程中的角色 |
| :--- | :--- |
| **Gemini 影片理解（手冊已有 `T-132`，待試）** | 拿到海選清單的 YouTube 網址後，**不用下載**就能先分析前 3 秒鉤子、段落結構與節奏類型，輔助負責人挑片。 |
| **[video_probe.py](../bin/video_probe.py) `breakdown`（本專案已有）** | 負責人同意下載後，自動切鏡、抽關鍵格、算出亮度／飽和度／畫面變化／字面積，接回 [direction.py](../bin/direction.py) 與 `L1–L4` 參考表。 |

## 5. 分階段實作藍圖

### Phase 1：MVP（零成本 YouTube / Shorts 海選閉環）
* **產出工具**：新增 `bin/ref_search.py`（或整合為 `pb.py ref-search`）。
* **輸入參數**：需求關鍵字、格式（`shorts` / `long`）、時長上下限、最多回傳筆數（預設 10）。
* **運作邏輯**：
  1. 先比對本地參考庫，列出已有的同類型影片。
  2. 透過 `yt-dlp`（`ytsearch` + `--match-filter`）或 YouTube Data API v3 撈取候選影片並計算 `Views / Subs`（若有 API Key 則加計頻道近期中位數的 Outlier Score）。
  3. 產出結構化清單（Markdown 表格或本機 HTML 卡片頁，含縮圖、標題、片長、觀看數、離群倍數、網址）。
* **驗收標準**：不下載任何影片的情況下，1 分鐘內產出 5–10 支同類型候選範本，供負責人勾選。

### Phase 2：與 `direction.py` 及 `video_probe.py` 打通
* 負責人勾選 2–3 支並核准下載後，自動呼叫 `yt-dlp` 下載至專案暫存參考目錄並執行 `video_probe.py breakdown`。
* 將這幾支外部範本的關鍵格與量化軸（每鏡秒數、亮度、飽和度、畫面變化、字面積）直接注入 `direction.py` 的參考牆，讓二選一與參考牆同時包含「通用樣本＋本次實戰範本」。
* 更新 [01-研究與參考.md](../guide/01-研究與參考.md) 的步驟編號與過關條件。

### Phase 3：跨平台與免下載初篩擴充（依需求選配）
* 接入 **Gemini 影片理解（`T-132`）**：對海選清單自動補上一句話「開頭鉤子與結構摘要」，降低負責人人工點開每支片確認的時間。
* 視商業投流需求，增加 **Meta Ad Library / TikTok（Apify 或 MCP）** 作為第二搜尋來源，並加上費用預估確認機制（`S0-10`）。
