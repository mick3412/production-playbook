# Production Playbook

影片與素材製作的手把手手冊。依十個製作階段，告訴你（和 Claude）每一步要做什麼、用什麼工具、要注意什麼、怎麼做得更好；同時持續收錄新做法和新工具，再用實際製作的結果修正手冊。

不綁任何產品。品牌色、字型、用語和合規限制放在各產品自己的專案裡，手冊只在開案階段（0.4）提醒你去讀。

## 階段

| # | 階段 | 產出 |
|---|---|---|
| 0 | 開案 | brief |
| 1 | 研究與參考 | 參考拆解、風格主提示詞 |
| 2 | 腳本 | 核准稿 |
| 3 | 分鏡與規格 | 分鏡規格 |
| 4 | 素材 | 素材清單＋授權表 |
| 5 | 製作 | 可預覽的 composition |
| 6 | 審片 | 修改清單 |
| 7 | 算圖與混音 | 母帶 |
| 8 | 交付與發佈 | 成品＋零件包 |
| 9 | 回顧與收錄 | 實戰紀錄 |

另有兩條跨階段軌道：**協作**（怎麼交代、怎麼審）、**工具**（安裝、授權、費用、資安）。素材類型分成影片、口播、圖卡、縮圖、網頁，階段卡可以只顯示某一類的條目。

每個階段的完整清單在 [`guide/`](guide/README.md)，由資料自動產生。

## 安裝（Claude Code 外掛）

```bash
python3 pb.py setup                                   # 記住 repo 位置，寫入一律回到這裡
claude plugin marketplace add "<這個 repo 的路徑>"
claude plugin install production-playbook@production-playbook-local
```

裝好後在任何專案都有：

- **技能 `production-playbook`**：說「做一支影片」「寫腳本」「這段字幕怎麼改」或丟來一個連結時自動載入。
- **斜線指令**：`/pb-start`、`/pb-status`、`/pb-next`、`/pb-card`、`/pb-add`、`/pb-review`、`/pb-pause`、`/pb-done`。
- **hook**：專案裡有進行中的作品時，開新對話會先列出作品，之後每則訊息附一行「目前／下一步／未過關」。沒有進行中的作品時完全不輸出。

更新資料後，用 `claude plugin update production-playbook` 讓外掛拿到新版本。

## 指令

| 指令 | 用途 |
|---|---|
| `pb.py card <階段> [--type 類型] [--brief]` | 看階段卡；`--brief` 只給五行提醒 |
| `pb.py start <名稱> --type <類型>` | 在目前的專案開一支作品（進度存在專案的 `.production/active.json`） |
| `pb.py status`、`list`、`use <名稱>` | 看進度、列出作品、切換作品 |
| `pb.py check-off <代號…>`、`--undo` | 勾掉步驟（`3.1`）、過關條件（`G3.1`）、條目（`S6-02`）或工具（`T-46`，表示這支作品不適用、不再提示）；任何階段的代號都可以先勾，不認得的只會略過 |
| `pb.py advance`、`back <階段>` | 進下一階段（過關條件沒勾完會擋下）、退回某階段 |
| `pb.py pause`、`resume`、`done` | 暫停、恢復、完成 |
| `pb.py show <代號>` | 看一條做法或一個工具的完整內容 |
| `pb.py inbox add <網址或檔案> --note "…"`、`inbox list` | 先把新資料丟進 inbox（網址的追蹤參數會自動拿掉） |
| `pb.py similar "<要點>"` | 收錄前找相近的條目，決定合併、新增或標成爭議 |
| `pb.py next-id <階段>` | 下一個可用的條目代號 |
| `pb.py run-log --entries S6-02,S3-01 --result 有效 --note "…"` | 記錄這支作品用了哪些條目、效果如何 |
| `pb.py review` | 依實戰紀錄和複查條件，列出升級、降級、複查、移到 archive 的建議 |
| `pb.py build`、`check` | 重新產生 `guide/`；驗證資料並確認 `guide/` 是最新的 |
| `pb.py log "<訊息>"` | 在 `data/changelog.md` 加一行 |

## 資料

| 檔案 | 內容 |
|---|---|
| `data/stages.json` | 階段、步驟（可標「適用類型」，例如口播粗剪只出現在口播）、過關條件、下一步 |
| `data/entries.csv` | 做法：階段、步驟、類型、素材類型、觸發、要點、做法、為什麼、來源、證據、實用度、狀態 |
| `data/tools.csv` | 工具：階段、步驟、素材類型、何時用、授權、費用、狀態、安裝方式、複查條件 |
| `data/sources.csv` | 來源；容易消失的原文存在 `sources/` |
| `data/runs.csv` | 實戰紀錄 |
| `data/changelog.md` | 每次收錄、迭代改了什麼 |
| `archive/` | 移出主線的條目和工具（保留，不刪除） |

只有 `data/` 是手改的；`guide/` 一律用 `pb.py build` 產生。條目代號一旦發出就不改、不重用。

**欄位值**

- 類型：要做、檢查、工具、提升、陷阱、知識
- 狀態：已內建（寫進階段卡或技能）、採用、待試、參考、避開、爭議
- 證據：單一來源、多來源、實戰驗證
- 工具狀態：已整合、已安裝、待試、待查（費用或授權不明）、未採用、避開

## 收錄新資料

可以隨時把連結、截圖、PDF、影片丟進來，任何專案、任何 agent 都可以。流程寫在技能裡，摘要如下：

1. 讀內容；和影片或素材製作無關的不收。
2. 拆成條目，用 `similar` 和既有條目比對：講同一件事就**合併**（加來源、提高證據等級），新做法就**新增**，互相矛盾就兩條都標**爭議**，等實戰決定。
3. 工具要查授權、費用和最後更新日；不明的標「待查」。
4. 登記來源，跑 `build`、`check`、`log`，然後 commit。

## 測試

```bash
python3 -m unittest discover tests
```

只用 Python 標準函式庫，不需要安裝任何套件。
