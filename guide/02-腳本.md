# 2 腳本

內容決定一切；包裝再好，訊息不對觀眾也不會留下來。

**這一步要產出：** 核准稿

## 要做

- [ ] **2.1 六要素**：角色、受眾、主題、架構（前 3 秒、中段、結尾）、秒數、語氣一次給齊；改版時稿子已核准，2.1–2.3 可以略過，直接做 2.4
  - 腳本提示詞固定六要素（S2-01）
  - 開場前 15 秒要做三件事，不放頻道介紹和訂閱呼籲（S2-13，待試）
  - 口播稿要附語調備註（S2-10，待試）
  - 把喜歡的影片台詞交給 AI，整理出固定的敘事結構（S2-12，待試）
  - 讓人看到最後：先預告回報、標出終點、最好的放最後、一定兌現（S2-14，待試）
  - 短片腳本骨架：鉤子 → 鎖定區 → 內容段 → 再鉤 → 內容段 → CTA；再鉤放在 20–25 秒（S2-16，待試）
- [ ] **2.2 發散再收斂**：先發散 3–5 個內容角度，代理收斂成 2–3 個，每個寫一句鉤子、核心訊息和為什麼；【決策窗 B 方向】交負責人選一個（可和 1.0 方向樣片同一次給），選定後才展開成完整腳本；負責人不選時寫明「代理代選」和理由
  - 開場一次寫多個，從不同角度切，再挑最好的三個（S2-07，待試）
  - 腳本先發散再收斂（S2-02）
- [ ] **2.3 具體化**：形容詞換成看得到的動作和數字；字數照分鏡模板的字數預算（英文 ≤2.5 字／秒、中文 4–5 字／秒），合規小字是必填槽，寫稿時就跑專案的合規檢查
  - 抽象形容詞換成動作和感官細節（S2-03）
  - 腳本與畫面互相支撐：旁白沒畫面支持就刪、問題用場景演（S2-15，待試）
  - 知識型解說片開頭 10 秒：先講結論，再預告這支講哪幾件事（S2-18，待試）
- [ ] **2.4 腳本關卡**：程式檢查（專案的合規檢查）先過，再做腳本複審（必做）：`pb.py review-pack --stage script --files 稿.md [事實表.md] --brief "需求"` 產生審查包 → 派一個新的 video-reviewer 子代理（第一輪：觀眾，前 3 秒會不會停、學到什麼；第二輪換另一個新代理：專家挑錯、事實與數字對專案的事實登記表、合規）；已核准的稿也要過。報告寫清每條意見怎麼處理，以及改稿後要重配音的鏡頭和總長變化。【決策窗 C 稿件】兩份報告附給負責人核准
  - 檢查：配音前先過腳本關卡（S2-04）
  - 檢查：腳本裡的成果、數字和案例要真實並取得授權；發布前用自己的語氣改一次（S2-11）
  - 旁白沒經負責人核准就不做配音；改一句就要重新核准（S2-17）
