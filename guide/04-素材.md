# 4 素材

把畫面、聲音、字型備齊，而且每一樣都能合法使用。

**這一步要產出：** 素材清單＋授權表

## 要做

- [ ] **4.1 實拍與圖庫**：挑素材前先看過畫面，確認內容和比例；大檔用可續傳下載並驗證完整，前處理後逐段比對長度
  - 真截圖勝過模擬畫面（S4-04，待試）
  - 檢查：照片先轉正，再檢查比例（S4-13）
  - 檢查：前處理後逐段比對片段長度，不足就補最後一格（S4-17）
  - 先規劃每段特效，再錄影；錄的時候頭頂和左右留空間（S4-18，待試）
  - 能拍 4K 就拍 4K，跳切放大才清楚（S4-23）
  - 拍攝規格小抄：一支一個訊息、一個主要特效，前後鏡曝光一致（S4-27，待試）
  - 要做去背特效的口播：腳架、胸上置中、背後有實物、每句停半秒（S4-32，待試）
- [ ] **4.2 生成素材**：生圖、生影片的提示詞；同一角色或場景用固定參考圖
  - 寫具體的光影、質感、細節清單（S4-05，待試）
  - 首尾幀釘住產品圖，避免失真（S4-06，待試）
  - 生成前先估成本、設總上限，單項超過門檻要人核准（S4-29）
  - 輪播一套：第 1 張定風格、其餘拿它當參考，逐張驗收，驗收後才排程發佈（S4-30，待試）
- [ ] **4.3 定稿配音**：依核准稿逐句生成定稿配音，依實際聲音裁切；第 3 階段的暫配要換掉
  - 配音每句分開生成（S4-15）
- [ ] **4.4 配樂與音效**：找可商用的來源，記下作者和授權
  - AI 配樂的風格用英文寫曲風、樂器、情緒，最後加 no vocals（S4-20，待試）
  - 音效先找真人錄音，找不到再用程式生，最後統一對位（S4-22，待試）
  - 從音效包影片切出單一音效：看音量找空白，不看畫面上的波形（S4-28，待試）
- [ ] **4.5 授權登記**：每個素材記來源、授權、是否需要標註
  - 沿用 MIT 程式碼要保留授權註解（S4-10）
- [ ] **4.6 口播粗剪**：真人錄影先剪氣口和停頓，同一句只留最後一個 take，故意留的停頓先標出來
  - 依逐字時間剪停頓，不剪進字裡（S4-12）
  - 口播節奏的具體數字：語速、停頓、接點（S4-26，待試）

## 用什麼工具

- **auto-editor**（T-01）：口播粗剪第一步：依音量剪掉停頓和空白；故意留的停頓要先排除
- **LosslessCut**（T-02）：手動挑素材、切長錄影，不重新編碼
- **DeepFilterNet**（T-09）：視訊或手機錄音的底噪
- **Demucs**（T-10）：素材混著背景音樂時，抽出乾淨的人聲
- **Kokoro TTS**（T-55）：免費、本機、沒有額度限制的英文配音；每句分開生成，時間精準（數字要先拼成英文字）。預設英文配音（2026-11-12 比較定案：和 Pocket TTS 字錯率同為 0%，Kokoro 授權 Apache-2.0 免標註、聲音選擇多）
- **Pixabay（影片與照片）**（T-57）：免費、可商用的實拍 B-roll；挑之前先看畫面，記下影片 ID
- **Poly Haven**（T-58）：3D 場景用的材質、HDRI 和模型
- **Kevin MacLeod（incompetech）**（T-59）：免費配樂；CC BY 4.0，說明欄一定要附標註
- **SenseVoice（SenseVoiceSmall）**（T-102）：中文為主的逐字稿：中、粵、英、日、韓；要快、要標出笑聲掌聲等聲音事件時。保留給多語自動辨識、情緒與聲音事件標籤；一定要配 fsmn-vad，否則遇停頓就截斷（P12）
- **FunASR（modelscope）**（T-103）：中文逐字稿要一次做完語音偵測、加標點、講者分辨時。中文逐字稿預設（P12：字錯率 0.8%／12.6%，最快）；輸出簡體無標點，用 OpenCC 轉繁、標點另外處理；講者分辨用 T-95，不用 CAM++（要 1.1 GB 標點模型）

**這一步可以試的新工具：**
- ClearerVoice-Studio（T-12，待試）：多人錄音要抽出單一講者的聲音時（降噪本身用 DeepFilterNet）；複查條件：有多人同時說話的錄音時
  - 測試方法：何時：有多人同時說話的錄音｜怎麼做：用 ClearVoice 抽出指定講者｜看什麼：其他人聲殘留、目標人聲是否失真｜有效＝殘留聽不清楚且目標人聲自然
- ACE-Step 1.5（T-60，待試）：需要長度剛好的配樂、又不想付費或擔心 Content ID 時；複查條件：下一支走到 4.4 配樂與音效 的作品
  - 測試方法：何時：需要長度剛好的配樂｜怎麼做：生成 3 版指定長度的配樂｜看什麼：長度準確、品質、Content ID｜有效＝至少一版可用且不被認領
- Stable Audio 3（Small／Medium）（T-61，待試）：要快、長度要準的純音樂；複查條件：下一支需要原創配樂或音效時
  - 測試方法：何時：下一支需要配樂的影片｜怎麼做：同一段 30 秒，用 Stable Audio 生成 3 版，跟現有免費曲庫各挑 1 首比｜看什麼：跟畫面節奏是否合、有沒有雜音、生成時間｜有效＝至少一版直接可用，且比找曲庫快
- Openverse 音訊搜尋（T-65，待試）：要找音效或配樂時先用它；複查條件：下一支走到 4.4 配樂與音效 的作品
  - 測試方法：何時：找音效或配樂時｜怎麼做：先在 Openverse 搜｜看什麼：找到可用素材的比例、授權標示｜有效＝一半以上的需求能在這裡找到
- youtube-agent-skill（11 個 YouTube 技能）（T-74，待試）：寫 YouTube 腳本與開場、檢查標題縮圖、剪停頓清單、做章節、讀留存、切 Shorts、找同領域爆款時；複查條件：開始經營 YouTube 頻道時
  - 測試方法：何時：開始經營 YouTube 頻道｜怎麼做：用它寫一支的開場、標題縮圖、章節｜看什麼：點閱率、3 秒留存｜有效＝不低於手寫版本
- Pixel2Motion（T-83，待試）：要把點陣圖 logo 做成片頭或網頁的 logo 動畫時；複查條件：有 logo 動畫需求時
  - 測試方法：何時：要做 logo 動畫｜怎麼做：把一個點陣 logo 轉 SVG 並做開場動畫｜看什麼：SVG 跟原圖疊合程度、動畫品質｜有效＝形狀沒跑掉且負責人核准
- story-to-handdrawn-video（T-84，待試）：要把中文故事或一組圖片做成手繪日記漫畫風的直式動畫時；複查條件：要做手繪風故事片、並接好生圖工具時（repo 628 MB）
  - 測試方法：何時：下一支故事型短片｜怎麼做：用 5 張現成圖片和一段故事做一支預覽版｜看什麼：手寫中文字是否正確、轉場、算圖時間、能否接配音｜有效＝預覽版可直接配音使用，中文字沒有錯
- banana-claude（T-88，待試）：要用 Gemini 生圖並由 agent 當創意總監時；複查條件：有自己的 Gemini 免費金鑰時（不用 ITA 專案的）
  - 測試方法：何時：下一次要生圖｜怎麼做：同一個需求用它和直接寫提示詞各生 3 張｜看什麼：可用張數、是否超出免費額度｜有效＝可用張數較多且沒超額
- Beeble（T-96，待查）：想把實拍場景換成另一個空間並重新打光時；複查條件：2026-12-10 或需要換場景時
  - 測試方法：何時：確認條款後｜怎麼做：用一段口播換一個場景｜看什麼：打光是否一致、邊緣、是否需付費｜有效＝免費額度內完成且看不出合成
- Adobe Podcast（Enhance Speech）（T-97，待查）：人聲錄音很差、DeepFilterNet 救不回來時；複查條件：2026-12-10 或 DeepFilterNet 處理不了時
  - 測試方法：何時：DeepFilterNet 處理不了的錄音｜怎麼做：同一段各處理一次並排聽｜看什麼：底噪、音色是否變｜有效＝明顯勝過 DeepFilterNet 且音色不變
- parakeet-mlx（T-104，待試）：英文或歐洲語言的逐字稿要在 Apple Silicon 上跑得很快時；複查條件：下一支英文口播要逐字稿時
  - 測試方法：何時：桌上試驗｜怎麼做：同一段英文口播和 faster-whisper 各轉一次｜看什麼：字錯率、逐字時間、速度｜有效＝字錯率不高於 faster-whisper 且快 2 倍以上
- whisper.cpp（T-105，待試）：不想裝 Python、要在命令列或其他程式裡直接跑 Whisper 時；複查條件：需要不靠 Python 的轉錄時
  - 測試方法：何時：桌上試驗｜怎麼做：同一段口播和 faster-whisper 各轉一次｜看什麼：字錯率、速度、記憶體｜有效＝結果相同且不需 Python 環境
- pyannote-audio（T-107，待查）：講者分辨要最準時；模型要 Hugging Face 帳號、同意條款與 token；複查條件：負責人願意建 Hugging Face 帳號時
- Scriberr（T-110，待試）：要一個自架的網頁介面，批次上傳音檔轉錄時；複查條件：要批次轉錄多個音檔時
  - 測試方法：何時：桌上試驗｜怎麼做：上傳 3 個音檔批次轉錄｜看什麼：操作步驟數、結果品質｜有效＝比命令列省事且結果相同

## 要注意

- 品牌 Logo 只用正式檔案或真實截圖（S4-02）
- 寫進規格前先看過素材畫面（S4-14）
- 大檔要用可續傳的方式下載，下載後驗證完整（S4-16）
- 免費音樂網站的曲子常登記 Content ID，上 YouTube 會被認領（S4-19）
- 生圖模型畫出來的字常是錯的，畫面文字要另外疊上去（S4-21）
- 原始影片不要先壓字幕（S4-01）
- iPhone HDR 素材要先轉成 SDR，膚色才自然（S4-24）
- 生成一群人時，指定不同的臉型、年齡和體型（S4-31，待試）
- 不要：不要拿別人的影片當畫面（S4-09）
- 不要：不要用 YouTube 轉 mp3 和來源不明的音效網站（S4-25）
